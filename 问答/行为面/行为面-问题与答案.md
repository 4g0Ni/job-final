# 行为面 / 项目复盘问题与答案

> 使用 STAR/CAR，但不要背成流水账。每题准备 60–90 秒版和 3 分钟深挖版；数字、主语和完成度必须与简历一致。

### 1. 请做 2 分钟自我介绍。
我是刘启仁，本硕毕业于电子科技大学，过去四年在 Microsoft Advertising 做软件工程。工作内容分为三条主线：第一是在公司内设计并实现分层图 RAG 与多智能体 Commit 分析系统；第二是广告 UI 项目，包括图片素材质量预测、第三方监测、Media Deal、推荐、质量工程，以及关键向导 P95 40%–72% 的性能优化；第三是广告后端项目，重点包括图片资产生命周期治理、Deal 自动同步、推荐视频批处理和第三方测量服务。下一步我希望继续把大型工程、产品交付和 Agent 能力结合到 AI 应用工程中。

### 2. 你为什么想换工作/选择 AI 应用方向？
不要说“传统开发没前途”。可答：我已有大型系统、数据和产品交付基础，公司内的分层图 RAG 与多智能体 Commit 分析项目让我看到，Agent 系统真正难的是可靠交付、评测、延迟、成本和安全，而这些正好与我的工程优势重合。下一步希望继续在真实用户和生产约束下深入 AI 应用与 Agent 工程。

### 3. 你最有代表性的 AI contribution 是什么？
优先讲公司内的 Commit AI Resolver：从 JSON source of truth、SQLite FTS5 + sqlite-vec 混合召回、加权 RRF，到多阶段编排、Evaluator 有界重试和 6 个 MCP 工具；再补充 adocag-server 的 AST 分块、Leiden 社区与分层图 RAG。图片广告素材质量预测只作为产品/API 集成能力补充：主要调用 AIGC 团队提供的 API，并负责异步轮询、partial render、遥测和 A11y，不将其作为核心 AI 算法贡献。

### 4. 讲一个最难的性能问题。
Situation：广告组向导 P95 8–10 秒。Task：判断 UI、网络还是后端瓶颈并在不破坏复杂业务规则下提速。Action：增加分段遥测，用 React Profiler 找重渲染；懒渲染隐藏 Backbone 面板、稳定 props/state；预热和拆分可缓存请求，绕过非必要初始 API，并与 MT/MDS 协作。Result：编辑 10s→2.8s，创建 8s→2.7s，Native 创建 6s→3.6s。复盘要强调团队成果与个人负责项。

### 5. 讲一次从 0 到 GA 的项目。
选第三方监测。按需求背景→厂商/广告形态组合复杂度→数据模型与校验→和 MT 的错误码契约→测试矩阵→pilot 灰度→遥测与 GA 展开。不要只罗列 IAS/DV/ISPOT 名字，要讲如何控制组合爆炸和线上误伤。

### 6. 讲一次你犯的错误或方案不足。
可讲 Commit AI Resolver 最初把 date、author、risk 与语义文本一起 embedding，过滤又发生在全局 KNN 之后；在 2,300 条数据上不明显，但扩大到公开历史语料时会造成语义污染和过滤漏召回。我随后把结构化字段移回 metadata，加入 FTS5 通道、窄条件先过滤后精确 cosine、索引契约和回归测试。复盘重点是：小规模“能跑”不代表检索语义正确，索引设计必须从失败模式和可重建性出发。

### 7. 讲一次线上故障/高压处理。
用 DRI 案例：先明确影响面和是否需要止血；Kusto 看错误趋势、受影响 tenant/版本；关联发布与 commit；用 feature flag/回滚控制影响；复现、修复、验证后逐级恢复；最后补监控和测试。回答重点是冷静、证据链和沟通节奏，而不是英雄主义。

### 8. 如何处理和后端/数据团队的分歧？
先把争议转为共同目标和可测指标。例如性能问题用分段 trace 区分 UI、MT、MDS 时间；契约分歧用错误码、schema 和兼容策略落文档；无法一次统一时用 feature flag/A-B 小流量验证。描述一个你改变观点或折中方案的实例更加分。

### 9. 你如何确定优先级？
按用户/业务影响、风险、紧迫性、依赖和投入排序。P0 先止血；AI 功能优先做评测和安全边界再增加自主性；性能先攻关键路径和 P95，不在低影响组件过度优化。对外明确不做什么以及重新评估时间。

### 10. 你如何保证自己没有夸大团队成果？
用三层主语：平台规模用“项目/团队”；自己负责用“我实现/主导的模块”；协同成果用“我们共同交付”。准备 commit/设计/指标证据。比如 90+ 作业是仓库规模，性能总体数字是团队生产结果，而 partial render、具体遥测和 A11y 修复是个人贡献。

### 11. 讲一个你推动质量改进的例子。
可讲 Enzyme 到现代测试框架迁移、A11y 焦点治理或数据幂等回填。结构：原有失败模式→为什么单点修补不够→沉淀规则/工具/测试→如何验证和推广。展示你不仅修 bug，还降低同类问题复发率。

### 12. 你如何快速熟悉十万文件级 monorepo？
先从用户入口和运行时链路定位 package；读路由、组件、数据 hook/API、后端契约和遥测；用 git 历史找领域 owner 和设计演化；缩小到具体 package 后再构建/测试，避免全仓扫描。先形成架构图与验证假设，再改代码。

### 13. 讲一次技术选型。
选 SQLite FTS5 + sqlite-vec：当前真实验证规模约 2,300 条、34 天窗口，嵌入式单文件便于本地打包、审计和从 JSON 重建；关键词与 dense 召回通过 RRF 融合，窄 metadata 条件先过滤再精确排序。专业向量库在这个规模是过度设计；当候选达到数十万以上、暴力扫描 P95 不达标，或出现多租户、高并发、复杂 pre-filter 与高可用需求时，再基于真实 benchmark 迁移 ANN/HNSW 引擎。

### 14. 如果面试官指出你的项目不是真正的 Agent，怎么回答？
承认并精确定义：`adocag-server` 当前是有界 deep-research/Graph RAG pipeline；`commit-ai-resolver` 是固定角色加 evaluator 重试的 agentic workflow。说明自主性是连续谱，先用有界流程控制可靠性和成本；在有 eval 后再引入动态规划。这比争辩术语更可信。

### 15. 讲一个失败或未达到预期的项目。
选择真实案例，避免编造。可以讲某项 AI 改进仍停留在设计：没有 golden set 就无法证明检索模式更好。你因此把下一步从“继续加功能”改为先建立 Eval Harness。结果可以是获得了明确路线，不必强行包装成巨大成功。

### 16. 你收到过最有价值的反馈是什么？
建议准备真实反馈。回答应包含：反馈内容、你最初的反应、采取的具体变化、后续可观察结果。不要答“太追求完美”这种伪缺点。

### 17. 你的优势是什么？
“一纵两横”：纵向能在大型广告产品把复杂功能做到 GA；横向一是数据/指标，能用遥测和统计验证效果；二是 AI/Agent，能做 RAG、编排和 MCP。用三个证据分别支撑，不要只列形容词。

### 18. 你的短板是什么？
可诚实说：没有基础模型训练/大规模 GPU 训练的生产经验，强项是 AI 应用工程而非算法研究；或个人 Agent 项目的自动 Eval/可观测性仍在补齐。随后说明已有学习/落地计划。不要声称自己不会岗位核心能力。

### 19. 未来 2–3 年规划？
成为能对 AI 应用效果与生产可靠性共同负责的工程师：不仅接模型 API，还能定义 eval、检索/工具架构、观测、安全和成本，并带动团队把原型变成可持续产品。

### 20. 为什么选择我们？
必须按公司定制：产品是否有真实 Agent 使用场景；团队是否拥有数据闭环和评测基础；岗位是否需要大型工程与 AI 的结合。引用 JD/产品的具体一两点，再说明你的经历如何补位，避免泛泛夸行业前景。

### 21. 你会问面试官什么？
- 团队如何定义 Agent 功能“成功”，当前最关键的离线/在线指标是什么？
- 现阶段最大瓶颈在模型、数据、评测、工具可靠性还是产品闭环？
- 从原型到生产，权限、安全与成本由谁负责？
- 入职三个月最希望这个岗位交付什么？

### 22. 如果给你一个月改善现有 Agent，你怎么做？
第一周基线与失败分类；第二周建立最小 golden set、trace 和成本指标；第三周修 Top badcase（检索/工具/上下文）；第四周灰度验证和文档化。明确不会一开始就换模型或上复杂多 Agent，因为没有基线无法判断收益。
