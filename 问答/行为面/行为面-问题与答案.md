# 行为面 / 项目复盘问题与答案

> 使用 STAR/CAR，但不要背成流水账。每题准备 60–90 秒版和 3 分钟深挖版；数字、主语和完成度必须与简历一致。

### 1. 请做 2 分钟自我介绍。
我是刘启仁，本硕毕业于电子科技大学，过去四年在 Microsoft Advertising 做软件工程。我的工作有三条主线：第一是 AI 应用工程，我设计并实现了面向多仓库历史变更与回归调查的 evidence-first 检索 Agent。它不是简单把 Commit 做 embedding，而是用 Direct SHA、FTS5、dense 与 metadata 多路召回，通过 RRF 生成候选，再由 Evidence Gate 决定回答、拒答或澄清，并用分层 Eval Harness 验证检索、引用和 Agent 重试。第二是大型广告 UI，我长期负责素材、监测、Deal、推荐和质量工程，并参与将关键向导 P95 降低 40%–72%。第三是广告后端项目，包括图片资产生命周期治理、Deal 自动同步、推荐视频批处理和第三方测量服务。下一步我希望把大型系统交付经验与可评估、可观测的 Agent 工程结合起来，负责真正能进入生产闭环的 AI 应用。

### 2. 你为什么想换工作/选择 AI 应用方向？
不要说“传统开发没前途”。可答：我已有大型系统、数据和产品交付基础，Commit AI Resolver 让我看到，Agent 系统真正难的不是接入模型，而是让检索证据、拒答边界、工具调用、评测、延迟和成本形成可靠闭环，这正好与我的工程优势重合。下一步希望继续在真实用户和生产约束下深入 AI 应用与 Agent 工程。

### 3. 你最有代表性的 AI contribution 是什么？
优先讲 Commit AI Resolver。我的核心贡献不是“接了一个向量库”，而是把历史 Commit 调查拆成可验证的多阶段系统：以 JSON source of truth 和版本化索引保证可审计、可重建；用 Direct SHA、FTS5、dense、metadata 与 weighted RRF 做候选生成；用 Evidence Gate 阻止弱证据进入生成；用 Evaluator 有界重试和 stale-result 检测控制 Agent；再用 75-case 分层 Eval Harness、逐 case trace 和 CI gate做回归。最后通过 6 个 MCP 工具把这些能力提供给 IDE Agent。图片广告素材质量预测只作为产品/API 集成能力补充：主要调用 AIGC 团队提供的 API，并负责异步轮询、partial render、遥测和 A11y，不将其作为核心 AI 算法贡献。

### 4. 讲一个最难的性能问题。
Situation：广告组向导 P95 8–10 秒。Task：判断 UI、网络还是后端瓶颈并在不破坏复杂业务规则下提速。Action：增加分段遥测，用 React Profiler 找重渲染；懒渲染隐藏 Backbone 面板、稳定 props/state；预热和拆分可缓存请求，绕过非必要初始 API，并与 MT/MDS 协作。Result：编辑 10s→2.8s，创建 8s→2.7s，Native 创建 6s→3.6s。复盘要强调团队成果与个人负责项。

### 5. 讲一次从 0 到 GA 的项目。
选第三方监测。按需求背景→厂商/广告形态组合复杂度→数据模型与校验→和 MT 的错误码契约→测试矩阵→pilot 灰度→遥测与 GA 展开。不要只罗列 IAS/DV/ISPOT 名字，要讲如何控制组合爆炸和线上误伤。

### 6. 讲一次你犯的错误或方案不足。
可讲 Commit AI Resolver 最初把 date、author、risk 与语义文本一起 embedding，过滤又发生在全局 KNN 之后；在早期约 2,300 条数据上不明显，但扩大到 10,000 条公开历史语料时会造成语义污染和过滤漏召回。我随后把结构化字段移回 metadata，加入 FTS5 通道、窄条件先过滤后精确 cosine、索引契约和 Eval Harness。复盘重点是：小规模“能跑”不代表检索语义正确，索引设计必须从失败模式和可重建性出发。

### 7. 讲一次线上故障/高压处理。
用 DRI 案例：先明确影响面和是否需要止血；Kusto 看错误趋势、受影响 tenant/版本；关联发布与 commit；用 feature flag/回滚控制影响；复现、修复、验证后逐级恢复；最后补监控和测试。回答重点是冷静、证据链和沟通节奏，而不是英雄主义。

### 8. 如何处理和后端/数据团队的分歧？
先把争议转为共同目标和可测指标。例如性能问题用分段 trace 区分 UI、MT、MDS 时间；契约分歧用错误码、schema 和兼容策略落文档；无法一次统一时用 feature flag/A-B 小流量验证。描述一个你改变观点或折中方案的实例更加分。

### 9. 你如何确定优先级？
按用户/业务影响、风险、紧迫性、依赖和投入排序。P0 先止血；AI 功能优先做评测和安全边界再增加自主性；性能先攻关键路径和 P95，不在低影响组件过度优化。对外明确不做什么以及重新评估时间。

### 10. 你如何保证自己没有夸大团队成果？
用三层主语：平台规模用“项目/团队”；自己负责用“我实现/主导的模块”；协同成果用“我们共同交付”。准备 commit/设计/指标证据。比如 90+ 作业是仓库规模，性能总体数字是团队生产结果，而 partial render、具体遥测和 A11y 修复是个人贡献。

### 11. 讲一个你推动质量改进的例子。
可讲 Enzyme 到现代测试框架迁移、A11y 焦点治理或数据幂等回填。结构：原有失败模式→为什么单点修补不够→沉淀规则/工具/测试→如何验证和推广。展示你不仅修 bug，还降低同类问题复发率。

### 12. 你如何快速熟悉十万文件级 monorepo？
先从用户入口和运行时链路定位 package；读路由、组件、数据 hook/API、后端契约和遥测；用 git 历史找领域 owner 和设计演化；缩小到具体 package 后再构建/测试，避免全仓扫描。先形成架构图与验证假设，再改代码。

### 13. 讲一次技术选型。
选 SQLite FTS5 + sqlite-vec：当前离线 Demo 已对 10,000 条公开 Commit 完整建库，嵌入式单文件便于本地打包、审计和从 JSON 重建；关键词与 dense 召回通过 RRF 融合，窄 metadata 条件先过滤再精确排序。在单机 Demo 和当前数量级下，专业向量库会增加部署与运维复杂度；当候选达到数十万以上、暴力扫描 P95 不达标，或出现多租户、高并发、复杂 pre-filter 与高可用需求时，再以 Recall—P95—内存 benchmark 决定是否迁移 ANN/HNSW，而不是只按数据条数选型。

### 14. 如果面试官指出你的项目不是真正的 Agent，怎么回答？
承认并精确定义：`commit-ai-resolver` 更准确地说是固定阶段加 Evaluator 反馈循环的有界 agentic workflow，不是完全自主的通用 ReAct Agent。它在运行时会抽取约束、改写查询、根据评估调整关键词或日期并提前停止，因此具备有限适应性；但主链路由工程师预先设计，以控制可靠性、延迟和成本。下一步是在已有 Eval 基线上增加 `rg + git` 原始证据精查，而不是为了“更像 Agent”盲目增加自主性。

### 15. 讲一个失败或未达到预期的项目。
可以讲 Eval 集的可信度边界：离开原公司后不能继续使用内部 case，于是基于公开 React Commit 重建了 75-case 验证集。第一版有较多程序生成和标题派生正例，而且 frozen split 是在早期阈值观察之后形成，因此即使 test 指标达到 100%，也不能包装成严格外部盲测。我把它重新定位为版本化工程回归基线，冻结 corpus/case hash、分离 dev/test，并把真正未见的人工 RCA holdout 和在线 LLM 全链路评测列为下一步。复盘重点是：评测不仅要能重复，还要诚实说明数据来源、泄漏风险与结论边界。

### 16. 你收到过最有价值的反馈是什么？
建议准备真实反馈。回答应包含：反馈内容、你最初的反应、采取的具体变化、后续可观察结果。不要答“太追求完美”这种伪缺点。

### 17. 你的优势是什么？
“一纵两横”：纵向能在大型广告产品把复杂功能做到 GA；横向一是数据/指标，能用遥测和统计验证效果；二是 AI/Agent，能做 RAG、编排和 MCP。用三个证据分别支撑，不要只列形容词。

### 18. 你的短板是什么？
可诚实说：没有基础模型训练/大规模 GPU 训练的生产经验，强项是 AI 应用工程而非算法研究；在 Agent 方向虽然已完成离线 Eval Harness、trace 和 batch runner，但还缺真实生产流量下的人工 RCA holdout、在线 LLM 全链路评测与长期反馈闭环。随后说明会通过人工标注规范、灰度流量和持续校准补齐，而不是声称已经解决所有可靠性问题。

### 19. 未来 2–3 年规划？
成为能对 AI 应用效果与生产可靠性共同负责的工程师：不仅接模型 API，还能定义 eval、检索/工具架构、观测、安全和成本，并带动团队把原型变成可持续产品。

### 20. 为什么选择我们？
必须按公司定制：产品是否有真实 Agent 使用场景；团队是否拥有数据闭环和评测基础；岗位是否需要大型工程与 AI 的结合。引用 JD/产品的具体一两点，再说明你的经历如何补位，避免泛泛夸行业前景。

### 21. 你会问面试官什么？
- 团队如何定义 Agent 功能“成功”，当前最关键的离线/在线指标是什么？
- 现阶段最大瓶颈在模型、数据、评测、工具可靠性还是产品闭环？
- 从原型到生产，权限、安全与成本由谁负责？
- 入职三个月最希望这个岗位交付什么？

### 22. 如果给你一个月改善现有 Agent，你怎么做？
第一周基线与失败分类；第二周建立最小 golden set、trace 和成本指标；第三周修 Top badcase（检索/工具/上下文）；第四周灰度验证和文档化。明确不会一开始就换模型或上复杂多 Agent，因为没有基线无法判断收益。
