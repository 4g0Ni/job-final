# 06｜生产工程与部署（10 题）

记忆链：**服务接口 → 并发与流式 → 租户与事务 → 部署扩缩 → 测试发布**。

## ENG-01｜Python/FastAPI 的生产服务要注意什么？

**关键词：** **Async**、**Blocking I/O**、**Worker**、**Timeout**、**Validation**、**Observability**  
**关联：** ENG-02、ENG-09

**参考答案：** 我做 FastAPI 服务时，第一步会用 **Pydantic/Schema** 把输入输出边界收紧。网络和数据库 I/O 可以用 async，但 CPU/GPU 重任务不能直接堵在事件循环里，要放线程池、任务队列或者独立服务。连接池、超时、取消、限流和健康检查也要配好。多 Worker 环境下，会话状态尽量外置，同时默认接入 **Trace、结构化日志、指标和异常分类**。

## ENG-02｜SSE、WebSocket 和普通 HTTP 如何选？

**关键词：** **单向流**、**双向通信**、**重连**、**背压**、**取消**、**事件序号**  
**关联：** ENG-01、AGENT-03

**参考答案：** 我会按交互方向来选。普通 HTTP 适合一次请求一次返回；**SSE** 适合服务端持续向浏览器推 token 或任务状态，简单而且重连方便；真正需要双向、低延迟交互时再用 **WebSocket**。Agent 的流式接口还要定义事件类型、序号、心跳、取消和最终状态，并处理断线重连和背压。模型吐出来的每个碎片只是中间事件，不能直接当最终答案。

## ENG-03｜多租户 Agent/RAG 如何隔离？

**关键词：** **Tenant ID**、**ACL**、**Namespace**、**Quota**、**Cache**、**Audit**  
**关联：** RAG-11、EVAL-11

**参考答案：** 多租户里最重要的一点是，**Tenant ID 必须来自可信身份上下文，不能让模型自己填**。数据库、向量检索、对象存储、缓存键、队列和日志都要带租户边界，关键查询由服务端强制过滤。每个租户还可以有自己的模型和工具 Allowlist、配额、并发和数据保留策略。最后要专门做越权测试，不能只看正常路径。

## ENG-04｜Agent 工具的副作用、幂等和事务怎样设计？

**关键词：** **Idempotency Key**、**Dry-run**、**Confirmation**、**Saga**、**Compensation**  
**关联：** AGENT-04、MCP-04

**参考答案：** 我会把查询和写入工具分开。写操作先给一个 **Dry-run** 或执行计划，高风险动作让用户确认，再用业务 **Idempotency Key** 防止重试时重复执行。跨系统流程通常用 Saga 和补偿，不会指望模型维持分布式强事务。外部操作 ID 和真实状态都要记录，恢复时先查系统事实。模型可以建议动作，但事务边界必须由确定性代码控制。

## ENG-05｜自托管模型用 vLLM/TGI 时要关注什么？

**关键词：** **Batching**、**KV Cache**、**Quantization**、**GPU Memory**、**Throughput**、**SLA**  
**关联：** LLM-09、EVAL-12、ENG-09

**参考答案：** 自托管模型时，我会用真实的输入长度和并发去测**吞吐、首 token 延迟、每 token 延迟、显存、稳定性和质量**。重点关注 Continuous Batching、KV Cache、张量并行、量化、模型加载和滚动升级。线上还要限制请求长度和并发，设计排队和降级，并监控 OOM、队列时间和 GPU 利用率。只看单请求 Benchmark 很容易得出错误结论。

## ENG-06｜什么时候用微调，什么时候用 RAG 或工具？

**关键词：** **Knowledge vs Behavior**、**Freshness**、**Citation**、**Calculation**、**Maintenance**  
**关联：** LLM-08、RAG-01

**参考答案：** 我会先判断问题属于哪一种：模型是**不会做、没看到、查不到，还是没法执行**。会变化、需要引用的知识用 RAG；精确计算、实时状态和外部动作交给工具；稳定行为、格式和术语可以考虑 SFT/LoRA；偏好和拒答再做对齐。实际系统往往是组合使用，而不是微调、RAG、工具三选一。

## ENG-07｜如何对 Prompt/Agent 策略做 A/B 测试？

**关键词：** **Randomization**、**Guardrail**、**Exposure**、**Primary Metric**、**Interference**  
**关联：** EVAL-06、EVAL-13

**参考答案：** 我会先让新 Prompt 或策略通过离线安全和回归门槛，再按用户或会话做稳定随机，避免同一个任务一会儿进 A、一会儿进 B。实验要提前定义**主指标、延迟/成本/安全 Guardrail、最小样本和完整版本**。低频高风险任务更适合先跑 Shadow 或人工审核。结果出来以后，除了显著性，还要看效应大小和具体失败桶。

## ENG-08｜怎样设计一个企业级 Agent 平台？

**关键词：** **Gateway**、**Runtime**、**Tool Registry**、**RAG**、**Policy**、**Eval**、**Tenant**  
**关联：** AGENT-03、MCP-09、EVAL-12

**参考答案：** 我会把企业 Agent 平台分成控制面和数据面。**控制面**管理模型、Prompt、工具、知识库、策略、版本和 Eval；**数据面**负责模型网关、Agent Runtime、检索、工具执行、流式事件和任务队列。横向再补身份和租户、权限审批、记忆、Trace、成本和审计。核心状态外置、接口版本化，高风险动作走人审。第一版先把单 Agent 和 Workflow 做稳，再根据证据决定要不要多 Agent。

## ENG-09｜如何做容量、性能与稳定性设计？

**关键词：** **Workload**、**P95**、**Queue**、**Backpressure**、**Rate Limit**、**Circuit Breaker**  
**关联：** RAG-06、EVAL-08、ENG-05

**参考答案：** 我会先根据输入长度、模型调用次数、工具延迟和并发量做一个 **Workload Model**，再分别找网关、检索、模型和工具的瓶颈。线上通过队列、限流、背压、超时、熔断、隔离舱和降级，避免一个慢下游拖垮整条链路。指标重点看 **P95/P99、队列时间、成功率、token/秒和单任务费用**，还会用故障注入验证恢复是不是真的有效。

## ENG-10｜AI 应用如何做测试与发布？

**关键词：** **Unit**、**Contract**、**Golden**、**Simulation**、**E2E**、**Canary**、**Rollback**  
**关联：** EVAL-03、EVAL-13

**参考答案：** 测试我会按层来做：确定性代码做单元和属性测试，工具、模型接口做 **Contract Test**，检索、门禁和引用用固定 Case，Agent 再用可控模拟器和真实 **E2E 回放**。非确定输出用 Rubric 和多次采样。CI 先跑快速回归，发布前再跑完整 Eval 和负载测试，然后 Canary、监控，并准备自动或人工回滚。
