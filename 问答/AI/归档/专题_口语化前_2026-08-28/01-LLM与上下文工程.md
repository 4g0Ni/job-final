# 01｜LLM 与上下文工程（9 题）

记忆链：**模型如何生成 → 上下文如何承载 → 输出如何约束 → 训练/选型如何决策**。

## LLM-01｜为什么主流生成式大模型多采用 Decoder-only？

**关键词：** 自回归、因果掩码、统一目标、Scaling、KV Cache  
**关联：** LLM-02、LLM-03、ENG-05

**参考答案：** Decoder-only 用同一个“预测下一个 token”目标覆盖预训练、对话、代码和工具调用，数据管线简单，规模化规律清晰；因果注意力天然适合逐 token 生成，并能用 KV Cache 复用历史计算。它不是所有任务都绝对更优：纯编码、双向理解或严格条件生成仍可能适合 Encoder 或 Encoder-Decoder。

**易错点：** 不要说“Decoder-only 能看到未来 token”；训练时有整段输入，但因果掩码禁止关注未来位置。

## LLM-02｜Causal LM、Prefix LM 与 Encoder-Decoder 有什么区别？

**关键词：** attention mask、前缀双向、因果生成、条件生成  
**关联：** LLM-01、LLM-03

**参考答案：** Causal LM 中每个位置只看左侧；Prefix LM 允许前缀内部双向注意，但生成区仍是因果的；Encoder-Decoder 则让 Encoder 双向编码输入，Decoder 通过交叉注意力生成。面试时应从“信息可见性、训练目标、推理缓存和适用任务”四个维度比较，而不是只背结构名称。

## LLM-03｜RoPE、上下文窗口和“无限长输入”是什么关系？

**关键词：** 相对位置、外推、训练分布、注意力成本、检索  
**关联：** LLM-04、RAG-13

**参考答案：** RoPE 把位置信息编码进 Q/K 的旋转角度，有利于表达相对距离，但不会自动带来无限上下文。窗口仍受模型配置、训练长度、位置外推质量、KV Cache 显存和注意力复杂度限制。工程上先做检索、压缩、分层摘要和证据选择，再考虑扩大窗口；“能塞进去”不等于“能稳定利用”。

## LLM-04｜长对话怎样做 Context Engineering？

**关键词：** working set、压缩、摘要、检索、预算、来源  
**关联：** LLM-03、MCP-06、MCP-07、EVAL-08

**参考答案：** 先把上下文分成系统规则、任务状态、最近对话、长期记忆、检索证据和工具结果，并给每类设预算与优先级。保留原始关键约束和可追溯引用，对陈旧对话做结构化摘要，对外部知识按需检索，对工具输出做裁剪；每次压缩都记录版本和丢失信息，防止摘要漂移。

## LLM-05｜Context Engineering 与 Prompt Engineering 有何区别？

**关键词：** 指令、证据、状态、工具、动态装配  
**关联：** LLM-04、AGENT-03、RAG-01

**参考答案：** Prompt Engineering 主要优化“怎么写指令”；Context Engineering 关心模型本轮实际看到的全部信息，包括指令、历史、记忆、检索证据、工具 schema、工具结果和输出格式。生产 Agent 的质量瓶颈通常不只是一句话怎么写，而是是否把正确、最小、可信、顺序合理的上下文送进模型。

## LLM-06｜如何处理结构化输出不稳定？

**关键词：** JSON Schema、约束解码、验证、修复、重试  
**关联：** AGENT-06、AGENT-07、EVAL-03

**参考答案：** 优先使用模型原生 structured output 或 function calling，并提供窄而明确的 JSON Schema；服务端必须再次做类型、枚举、范围和业务校验。失败时先用确定性解析/修复，再带错误摘要做有界重试，仍失败则降级或人工处理。不能因为“模型通常会输出 JSON”就直接执行副作用工具。

## LLM-07｜DPO、PPO、GRPO 的核心差异是什么？

**关键词：** 偏好对、奖励模型、策略梯度、参考策略、组内优势  
**关联：** LLM-08、EVAL-02

**参考答案：** DPO 直接用偏好对优化策略与参考模型的相对概率，不需要在线 rollout 和独立奖励模型，工程简单但依赖偏好数据质量；PPO 是基于奖励的在线策略优化，能力强但链路复杂、稳定性和成本要求高；GRPO 用同一问题的多条采样做组内相对优势估计，减少对 value model 的依赖。三者都是对齐方法，不能简单说 DPO“不是 RLHF”或 GRPO“必然更好”。

## LLM-08｜SFT、LoRA/PEFT、偏好对齐与 RAG 应如何选？

**关键词：** 知识、行为、风格、时效、参数高效微调  
**关联：** LLM-07、RAG-01、ENG-06

**参考答案：** 外部知识频繁变化、需要引用和权限控制时优先 RAG；要让模型稳定学会格式、术语或任务行为时考虑 SFT；显存和训练成本有限时用 LoRA/PEFT；需要改善偏好、拒答和风格再考虑 DPO/PPO/GRPO。先用可评测的 prompt/RAG 基线证明瓶颈，再决定是否训练，避免用微调掩盖检索或流程问题。

## LLM-09｜生产系统如何选择和路由模型？

**关键词：** 质量、延迟、成本、上下文、工具能力、降级  
**关联：** EVAL-08、EVAL-12、ENG-05

**参考答案：** 先按任务定义质量门槛、结构化输出/工具能力、上下文、P95、吞吐、数据边界和单次成本，再用代表性数据做离线与影子评测。简单分类、改写交给小模型，复杂规划或困难样本升级到强模型；路由需有置信规则、预算上限、回退模型和版本记录。选型结论应来自质量—成本—延迟 Pareto，而不是只看榜单。
