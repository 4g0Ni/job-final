# 06｜生产工程与部署（10 题）

记忆链：**服务接口 → 并发与流式 → 租户与事务 → 部署扩缩 → 测试发布**。

## ENG-01｜Python/FastAPI 的生产服务要注意什么？

**关键词：** async、blocking I/O、worker、timeout、validation、observability  
**关联：** ENG-02、ENG-09

**参考答案：** 用 Pydantic/Schema 做边界校验；网络和数据库 I/O 使用 async，但 CPU/GPU 重任务放线程池、任务队列或独立服务，避免阻塞事件循环。设置连接池、超时、取消、限流和健康检查；多 worker 与有状态会话分离；trace、结构化日志、指标和异常分类默认接入。

## ENG-02｜SSE、WebSocket 和普通 HTTP 如何选？

**关键词：** 单向流、双向、重连、背压、取消、事件序号  
**关联：** ENG-01、AGENT-03

**参考答案：** 普通 HTTP 适合短请求；SSE 适合服务端向浏览器持续推 token/状态，协议简单且可自动重连；WebSocket 适合真正双向、低延迟交互。Agent 流式接口要定义事件类型、序号、心跳、取消和终态，处理断线重连与背压，不能把模型碎片直接等同于最终答案。

## ENG-03｜多租户 Agent/RAG 如何隔离？

**关键词：** tenant ID、ACL、namespace、quota、cache、audit  
**关联：** RAG-11、EVAL-11

**参考答案：** tenant ID 从可信身份上下文注入，不能由模型自由填写；数据库、向量检索、对象存储、缓存键、队列和日志都带租户边界，关键查询做服务端强制过滤。每租户配置模型/工具 allowlist、配额、并发和数据保留策略，并通过越权测试验证隔离。

## ENG-04｜Agent 工具的副作用、幂等和事务怎样设计？

**关键词：** idempotency key、dry-run、confirmation、saga、compensation  
**关联：** AGENT-04、MCP-04

**参考答案：** 读取与写入工具分离；写操作先展示 dry-run/计划，高风险动作要求确认，并使用业务幂等键防止重试重复执行。跨系统流程用 saga/补偿而不是幻想分布式强事务；记录外部操作 ID 和状态，恢复时查询真实状态。模型只提出动作，事务边界由确定性代码掌控。

## ENG-05｜自托管模型用 vLLM/TGI 时要关注什么？

**关键词：** batching、KV cache、quantization、GPU memory、throughput、SLA  
**关联：** LLM-09、EVAL-12、ENG-09

**参考答案：** 用真实输入长度和并发测试吞吐、首 token/每 token 延迟、显存、稳定性与质量；关注 continuous batching、KV Cache、张量并行、量化、模型加载和滚动升级。设置请求长度/并发上限、排队与降级，监控 OOM、队列时间和 GPU 利用率。框架选型不能只看单请求 benchmark。

## ENG-06｜什么时候用微调，什么时候用 RAG 或工具？

**关键词：** knowledge vs behavior、freshness、citation、calculation、maintenance  
**关联：** LLM-08、RAG-01

**参考答案：** 变化知识和需要引用的事实用 RAG；精确计算、实时状态和外部动作交给工具；稳定行为、格式、术语和领域表达可用 SFT/LoRA；偏好和拒答再做对齐。先定位错误属于“不会做、没看到、查不到还是不能执行”，再选手段；通常是组合而非单选。

## ENG-07｜如何对 Prompt/Agent 策略做 A/B 测试？

**关键词：** randomization、guardrail、exposure、primary metric、interference  
**关联：** EVAL-06、EVAL-13

**参考答案：** 先离线过安全与回归门槛，再按用户/会话稳定随机，避免同一任务跨版本污染；定义主质量指标、延迟/成本/安全护栏和最小样本，记录完整版本与曝光。对低频高风险任务优先影子或人工审核；显著性之外还要看效应大小和失败桶。

## ENG-08｜怎样设计一个企业级 Agent 平台？

**关键词：** gateway、runtime、tool registry、RAG、policy、eval、tenant  
**关联：** AGENT-03、MCP-09、EVAL-12

**参考答案：** 控制面管理模型、prompt、工具、知识库、策略、版本和 Eval；数据面包含网关、Agent Runtime、检索、工具执行、流式事件和任务队列；横向提供身份/租户、权限审批、记忆、trace、成本与审计。核心状态外置，接口版本化，高风险动作走人审；先支持单 Agent/Workflow，再按证据引入多 Agent。

## ENG-09｜如何做容量、性能与稳定性设计？

**关键词：** workload、P95、queue、backpressure、rate limit、circuit breaker  
**关联：** RAG-06、EVAL-08、ENG-05

**参考答案：** 用输入长度、模型调用数、工具延迟和并发构建负载模型；分别测网关、检索、模型和工具瓶颈。采用队列、限流、背压、超时、熔断、隔离舱和降级，避免下游慢导致级联故障；关注 P95/P99、队列时间、成功率、token/秒与单任务费用，并用混沌/故障注入验证恢复。

## ENG-10｜AI 应用如何做测试与发布？

**关键词：** unit、contract、golden、simulation、e2e、canary、rollback  
**关联：** EVAL-03、EVAL-13

**参考答案：** 确定性代码做单元/属性测试，工具与模型接口做 contract test，检索/门禁/引用用固定 case，Agent 用可控模拟器和真实端到端回放；非确定输出用 rubric 和多次采样。CI 先跑快速回归，发布前跑完整 Eval 与负载测试，再灰度、监控和自动/人工回滚。
